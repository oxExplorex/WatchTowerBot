# Офлайн-просмотрщик WatchTower

В боте откройте «Настройки → Бекапы переписок → Скачать просмотрщик · Windows».
Распакуйте скачанный `WatchTowerViewer-windows-x64.zip` и запустите `WatchTowerViewer.exe`.
Устанавливать Python или сам бот не требуется. Можно перетащить бекап ZIP или `.wtb` на EXE.

Для запуска из исходников используйте `view_archive.bat` из корня проекта либо:

```console
python -m archive_viewer
python -m archive_viewer "путь/к/бекапу.zip"
```

Для исходников нужен Python с установленной зависимостью проекта `cryptography`.
Бот, PostgreSQL, `.env` и интернет для просмотра не нужны в обоих вариантах.

Выберите ZIP или любую часть `.wtb`; остальные части должны лежать рядом. В открывшемся браузере введите личный секрет. Слева — чаты от свежих к старым и поиск по названию, ID и аккаунту. Справа — сообщения по дням, фото, видео, круглые видеосообщения, GIF-анимации, голосовые, аудио и стикеры WebP/WebM/TGS. Картинки, видео и аудио, присланные документом, тоже получают встроенный просмотр. Воспроизведение зависит от поддержки кодека браузером; оригинал можно скачать. Кнопка `⋯` и ПКМ открывают версии сообщения. Даты отправки, редактирования и сохранения ботом подписаны отдельно, в часовом поясе компьютера. Если исходный текст не был получен, история прямо сообщает об этом. Отметка недоступности при проверке отличается от подтверждённого удаления.

После обновления вкладки откройте заново ссылку из окна просмотрщика: токен доступа хранится только в памяти вкладки.

Интерфейс разделён на навигацию, переписку и сворачиваемый инспектор. Доступны поиск
по чату или всему архиву, фильтры по медиа и датам UTC, участники, галерея с догрузкой,
счётчики и граф направлений сохранённых личных сообщений. Проверка записей показывает
пропущенные данные; она не определяет подозрительное поведение людей. Слова и ссылки
в инспекторе считаются по последним 500 сообщениям, чтобы не блокировать большой архив.
Экспорт HTML/JSON сохраняет открытый текст и редакции; сами вложения остаются в бекапе.

Интерфейс обслуживается только на `127.0.0.1` со случайным портом и токеном доступа. Секрет передаётся локальному процессу на вашем ПК и не сохраняется. Внешних скриптов, CDN и запросов к Telegram нет. Расшифрованные вложения существуют в памяти; кнопка скачивания явно сохраняет выбранный файл. Временные файлы содержат только шифротекст и удаляются при завершении. Для закрытия процесса нажмите Ctrl+C в его окне. Закрытие вкладки само по себе не завершает процесс; используйте «Заблокировать», если отходите от компьютера.

Аватарки из доступных Telegram-данных сохраняются ботом в отдельной очереди с общими ограничениями запросов и шифруются личным ключом. Они попадают в новые бекапы после скачивания. В старых ZIP без аватарок или при недоступности фото остаются инициалы. Доступно только содержимое, которое бот успел сохранить. Проверка целостности всего бекапа выполняется до показа переписок. Для больших архивов она может занять время; поддерживается до 256 МБ метаданных и 128 МБ расшифрованных данных одного вложения.

## Обновления EXE

Внизу левой панели показаны версия приложения, номер сборки и результат проверки.
«Проверить обновление» повторяет проверку; при наличии новой сборки появляется «Обновить».
Перед установкой архив блокируется, затем приложение перезапускается. Для запуска
из исходников отображается отдельный статус: автообновление исходников не выполняется.

При запуске Windows EXE проверяет опубликованную сборку на GitHub, до открытия архива
и ввода секрета. Новая версия скачивается, проверяется по SHA-256 и самопроверкой EXE,
затем заменяет установленную и перезапускается. Рядом остаётся резервный `.exe.previous`.
Если обновление недоступно, запускается установленная версия; доступен флаг `--no-update`.
Исходники автоматически не изменяются. Бекап, путь к нему и секрет на GitHub не отправляются.

Старую сборку, в которой ещё нет механизма обновления, нужно один раз заменить вручную.
Последующие обновления она получит автоматически. Доверие к обновлениям основано на HTTPS
и контроле репозитория публикации; отдельной цифровой подписи EXE пока нет.

## Файлы медиа `.wtm`

WTM — контейнер проекта, а не новый алгоритм шифрования. В текущем формате WTM2
содержимое защищено AES-256-GCM со случайным ключом каждого файла. Этот ключ
зашифрован RSA-OAEP-SHA256 открытым ключом владельца; закрытый ключ хранится
зашифрованным и открывается личным секретом через Argon2id (64 МиБ, 3 прохода).
Документы перед шифрованием могут сжиматься без потерь; фото и видео не перекодируются.

Переименование файла или снятие проверки пароля не расшифровывает содержимое.
Слабый секрет можно подбирать при наличии зашифрованного закрытого ключа из БД
или бекапа. Размеры файлов и служебный заголовок не скрыты. Открытый просмотрщик,
его память и ввод секрета требуют доверенного компьютера.

Старый WTM1 использует серверный ключ, без личного секрета. Расширение у обеих
версий одинаковое; версия записана в первых четырёх байтах. Сам файл WTM2
не содержит закрытого RSA-ключа: для переносимого просмотра сохраняйте полный
бекап ZIP/WTB, в котором есть и зашифрованный набор ключей.

## Сборка и распространение

Workflow `Build archive viewer` собирает Windows x64 EXE после push изменений просмотрщика в `main`
или ручного запуска через GitHub Actions. Файл публикуется как asset релиза `archive-viewer`;
кнопка бота ведёт на его постоянный URL. До первой успешной публикации файл по ссылке отсутствует.
Сборка не читает секреты бота и не включает `.env`, БД или пользовательские архивы.

Для локальной сборки создайте отдельное окружение Python на Windows и установите
`archive_viewer/requirements-build.txt`, затем выполните `python scripts/build_archive_viewer.py`.
ZIP и SHA-256 появятся в `dist/archive-viewer/` (исключён из Git).
Перед упаковкой собранный EXE сам проверяет криптографию, тестовый архив и наличие HTML/CSS/JS
из временной папки за пределами репозитория. Сборщик не запускается на сервере бота и не входит
в его зависимости. Используется [PyInstaller](https://pyinstaller.org/en/stable/),
ресурсы упакованы [относительно модуля](https://pyinstaller.org/en/stable/runtime-information.html#placing-data-files-at-expected-locations-inside-the-bundle).

Для TGS встроен `lottie-web` 5.13.0, Canvas Light без поддержки выражений и внешнего CDN.
